# API модуля Jira

В Б5 добавлены запросы для бэклога, доски, карточки задачи и статуса синхронизации. Данные берутся из локальной базы модуля.

## Как пользоваться

Сначала нужно войти через `/jira/login/` под практикантом. После этого можно открывать API в том же браузере.

Все запросы используют метод GET. Практикант видит только свои задачи из включенных проектов.

## Бэклог

`GET /jira/api/backlog/`

Возвращает задачи вне активных спринтов.

Можно передать параметры:

- `sort` - сортировка: `rank`, `updated`, `key` или `priority`;
- `assignee` - account_id исполнителя;
- `status` - Jira ID статуса;
- `type` - тип задачи;
- `page` - номер страницы, начиная с 1.

Пример: `/jira/api/backlog/?sort=updated&page=1`

На странице до 20 задач. В ответе:

- `count` - сколько задач подходит под фильтры;
- `results` - задачи текущей страницы;
- `synced_at` - время последнего обновления данных среди подходящих задач.

Если задач нет:

```json
{
  "count": 0,
  "results": [],
  "synced_at": null
}
```

## Доска

`GET /jira/api/board/`

Возвращает активный спринт и задачи, сгруппированные по статусам.

Можно выбрать проект: `/jira/api/board/?project_key=DEMO`

Если подходящего спринта нет:

```json
{
  "sprint": null,
  "columns": [],
  "synced_at": null
}
```

## Карточка задачи

`GET /jira/api/issues/DEMO-1/`

Возвращает подробности задачи: название, статус, проект, исполнителя, спринт, метки и разрешенные дополнительные поля.

Связи показываются только с задачами, доступными этому практиканту. Для чужой и несуществующей задачи возвращается одинаковая ошибка 404.

Описание и комментарии пока отключены: `description_html` возвращается как `null`, а `comments` — как пустой список.

## Статус синхронизации

`GET /jira/api/status/`

Возвращает:

- `status` — состояние последнего запуска;
- `started_at` — когда он начался;
- `finished_at` — когда закончился;
- `synced_at` — когда закончилась последняя успешная синхронизация.

Если запусков еще не было, все значения будут `null`.

## Ошибки

- `400` — неправильные параметры запроса;
- `401` — пользователь не вошел;
- `403` — нет доступа, например вход под staff;
- `404` — задача, страница или адрес не найдены;
- `405` — использован неподдерживаемый метод;
- `500` — внутренняя ошибка.

Пример:

```json
{
  "error": "not_found",
  "message": "Задача не найдена."
}
```

Общие обработчики неизвестных API-адресов и внутренних ошибок возвращают JSON при `DEBUG=False`.

## Текущее поведение

Сейчас при нескольких активных спринтах выбирается самый поздний по дате начала среди доступных пользователю. В бэклог входят задачи без спринта, из будущих и закрытых спринтов.

Эти правила, формат статуса синхронизации и включение описаний и комментариев нужно обсудить на ревью.
